# Kavach — MVP Specification

> **Compress the delivery, not the knowledge.**

## 1. Product

**Kavach** converts educational PDFs into structured, source-grounded revision shorts.

A student uploads a PDF, Kavach understands the material, identifies important concepts, recommends a learning order, and generates short whiteboard lessons with AI narration and quick checks.

### Target users

* School students
* College students
* Students revising before exams
* Students working through dense technical study material

### MVP input

* One PDF per session
* Maximum **60 pages**
* Text-based PDFs
* Image/diagram extraction where practical
* OCR for scanned PDFs
* English content and narration

---


# 3. MVP Features

## 3.1 PDF Upload

Student uploads a PDF.

### Requirements

* Maximum 60 pages
* Validate file type
* Validate page count
* Store original PDF in Amazon S3
* Generate a unique `document_id`
* Display processing status

### Statuses

```text
UPLOADED
PROCESSING
ANALYZING
READY
GENERATING
COMPLETED
FAILED
```

---

# 4. PDF Analysis

Kavach should analyze the document before generating videos.

### Extract

* Text
* Headings
* Sections
* Important concepts
* Definitions
* Relationships between concepts
* Tables
* Diagrams/images where practical
* Equations/formulas
* Source page numbers

### PDF suitability check

Before generation, return:

```json
{
  "suitable": true,
  "page_count": 48,
  "quality": "good",
  "warnings": [],
  "recommendations": []
}
```

If the PDF is difficult to process:

```json
{
  "suitable": false,
  "quality": "poor",
  "warnings": [
    "Several pages contain low-quality scanned text."
  ]
}
```

The user can decide whether to continue.

---

# 5. Brain AI

## Responsibility

Amazon Bedrock acts as the **Brain AI**.

It should not simply summarize the PDF.

It should create a **teaching plan**.

### Brain AI tasks

1. Understand the document
2. Identify concepts
3. Identify relationships/prerequisites
4. Build a learning order
5. Recommend important topics
6. Estimate number of shorts
7. Decide whether a topic needs multiple shorts
8. Generate scripts
9. Generate visual instructions
10. Generate source references
11. Generate quick-check questions
12. Identify uncertainty
13. Separate PDF knowledge from AI-added context

---

# 7. Student Customization

The AI recommends topics, but the student controls the final selection.

Student can:

* Add topics
* Remove topics
* Keep recommended topics
* Reorder if desired

The system should then regenerate the learning plan.

---

# 8. Learning Order

The Brain AI recommends an order based on:

* Prerequisites
* Concept relationships
* Difficulty
* Logical teaching progression

Example:

```text
TCP fundamentals
       ↓
Connection establishment
       ↓
Three-way handshake
       ↓
Flow control
       ↓
Congestion control
```

No mastery score is required for the MVP.

---

# 9. Revision Shorts

Each selected topic becomes one or more short lessons.

### Constraints

* Target duration: **30–60 seconds**
* AI decides the number of shorts
* AI decides the appropriate duration
* A large topic may become multiple shorts
* Each short should explain a coherent concept

Example:

```text
TCP Three-Way Handshake

Short 1:
Why TCP needs a handshake

Short 2:
SYN → SYN-ACK → ACK
```

---

# 10. Teaching Plan JSON

Bedrock should produce structured JSON rather than unstructured prose.

Example:

```json
{
  "topic": "TCP Three-Way Handshake",
  "learning_order": 5,
  "parts": [
    {
      "part": 1,
      "title": "Why TCP Needs a Handshake",
      "duration_target": 42,
      "script": "Before TCP can transfer application data...",
      "visual_plan": [
        "Draw client",
        "Draw server",
        "Show connection request",
        "Animate the initial exchange"
      ],
      "sources": [24, 25],
      "ai_added_context": []
    }
  ],
  "quick_check": {
    "question": "Why does TCP use a three-way handshake?",
    "options": [
      "To establish connection state",
      "To encrypt all traffic",
      "To increase bandwidth",
      "To resolve DNS"
    ],
    "answer": 0
  }
}
```

This JSON is the contract between the **Brain AI** and the video renderer.

# 11. Whiteboard Video Generation

## Design principle

Videos should look like a clean educational whiteboard.

Not:

* Cinematic AI scenes
* Avatars
* Flashy transitions
* Random stock footage

Instead:

* White background
* Hand-drawn/educational visual style
* Diagrams
* Arrows
* Labels
* Equations
* Highlighting
* Simple animations

---

# 15. Source Grounding

Every generated short should show its source.

Example:

```text
Sources
PDF — Pages 24–26
```

If AI adds information not explicitly contained in the PDF:

```text
AI-added context
```

This distinction must be visible to the student.

---

# 16. Accuracy Behavior

The PDF is the primary source of truth.

The system should **not silently invent an interpretation** when the source is ambiguous.

Example:

```json
{
  "uncertainty": true,
  "reason": "The diagram on page 31 is partially unreadable.",
  "source_pages": [31]
}
```

The user should be warned when source quality limits confidence.

---

# 17. Quick Checks

After every short, show one or more quick questions.

Questions should test understanding rather than simple recall where practical.

Example:

> What is the purpose of the third ACK in TCP?

```text
A. Encrypt the connection
B. Confirm receipt of SYN-ACK
C. Resolve the server's IP
D. Increase packet size
```

Show the correct answer after the student responds.

---

# 18. Follow-up Q&A

Optional MVP feature.

After watching a short, the student can ask:

> "Why does the server send SYN-ACK instead of just ACK?"

The AI should answer using:

1. Original PDF
2. Generated lesson context
3. Relevant AI-added context, if enabled

Answers should include source references where possible.

---

# 19. Feedback & Regeneration

After each video:

```text
How was this explanation?

👍 Good
🤔 Didn't understand
🐢 Too fast
🧠 Too difficult
🔄 Explain differently
```

If the student chooses a negative option, regenerate the lesson with an adjusted teaching approach.

Example:

```text
Didn't understand
       ↓
Bedrock
       ↓
Simpler explanation
       ↓
New visual plan
       ↓
New video
```

---

# 20. AI-Enhanced Mode

### Default mode

Only use the uploaded PDF as the knowledge source.

### AI-Enhanced mode

Bedrock may add external/general knowledge to improve understanding.

Any added material must be explicitly marked:

```text
AI-added context
```

The distinction between source material and generated context must remain visible.

# 32. Product Principle

## Compress the delivery, not the knowledge.

Kavach should not merely summarize a 60-page PDF into five bullet points.

It should preserve the important knowledge while changing its **delivery format**:

```text
Dense PDF
    ↓
Structured knowledge
    ↓
Learning path
    ↓
Short visual lessons
    ↓
Active recall
```

The goal is **faster revision without throwing away the substance of the source material**.
